# SOC Incident Report — IR-009: Failed Logon Monitoring

## 1. Executive Summary

**Incident ID:** SOC-IR-009
**Category:** Authentication Monitoring / Potential Brute Force
**Environment:** Windows 11 lab endpoint
**Detection Platform:** Splunk Enterprise
**Telemetry Source:** Windows Security Event Log
**Status:** Authentication-monitoring exercise
**Severity:** Informational — Pattern assessment required
**Disposition:** Failed-authentication investigation

This exercise evaluates collection and analysis of failed Windows authentication events.

Windows Security Event ID 4625 provides evidence of an unsuccessful logon. Repeated failures may warrant investigation, but a single failed event does not establish brute-force activity.

## 4. Investigation and Analysis

Review the target account, source address, logon type, failure status, and timing.

Determine whether multiple events form a meaningful pattern. Consider whether the events involve one account, multiple accounts, one source, or several sources.

Distinguish authentication failures generated by normal system activity from behavior that may indicate credential guessing.

## 5. MITRE ATT&CK Mapping

**Candidate technique:** T1110 — Brute Force.

**Official reference:** https://attack.mitre.org/techniques/T1110/

Assign the technique only when the observed pattern supports a brute-force hypothesis.

## 6. Impact Assessment

* Brute-force attempt: Not established from a single failure.
* Successful account compromise: Not established.
* Unauthorized access: Not established.
* Account lockout: Verify separately if relevant.

## 7. Response and Containment

For repeated or high-confidence suspicious failures, investigate the source and target account. Follow account-protection procedures where warranted.

Do not lock accounts or block sources based on an isolated event without appropriate context.

## 8. False-Positive Considerations

Common causes include mistyped passwords, expired credentials, services using outdated credentials, and automated applications attempting authentication.

## 9. Limitations and Evidence Gaps

An isolated Event ID 4625 does not establish a brute-force attack or identify the actor responsible.

## 10. Recommendations

* Group failed logons by account, source, and time window.
* Validate detection thresholds against normal authentication activity.
* Correlate failures with successful logons where relevant.
* Review status and substatus codes carefully.

## 11. Final Disposition

**Disposition:** Failed-authentication monitoring exercise; brute-force activity not established without a supporting pattern.

**Validation status:** Failed-logon telemetry observed; focused detection validation requires documented results.

**Analyst Notes:** Windows Security Event ID 4625 provides evidence of an unsuccessful logon. The target account, logon type, source address, status, and event frequency should be reviewed. A single failed logon does not establish brute-force activity or account compromise.

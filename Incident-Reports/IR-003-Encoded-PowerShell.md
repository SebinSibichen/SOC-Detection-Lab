# Incident Report 04 - Suspicious PowerShell Encoded Command

## Incident Title

Suspicious PowerShell Encoded Command Execution

---

## Incident ID

IR-004

---

## Severity

Medium

---

## Status

Closed - Lab Simulation

---

## Detection Source

Splunk Enterprise

---

## Log Source

Microsoft-Windows-Sysmon/Operational

---

## Detection Event

**Sysmon Event ID 1 – Process Creation**

---

## Description

A PowerShell process was detected using an encoded-command parameter.

The activity was generated intentionally as part of a controlled SOC detection lab.

The simulated command was harmless and was used only to validate the detection capability.

---

## Detected Process

```text
powershell.exe
```

Expected path:

```text
C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
```

---

## Detection Logic

The Splunk detection searches for PowerShell processes where the command line contains:

```text
-EncodedCommand
```

```text
-Encoded
```

or:

```text
-enc
```

Splunk Universal Forwarder PowerShell processes are excluded to reduce false positives.

---

## SPL Detection Query

```spl
index=main EventCode=1
| search Image="*\\powershell.exe"
| regex CommandLine="(?i)(-encodedcommand|-encoded|-enc)(\s|$)"
| where NOT match(Image,"(?i).*SplunkUniversalForwarder.*")
| table _time ComputerName User Image ParentImage CommandLine ProcessId ProcessGuid
| sort - _time
```

## Investigation

The analyst should review:

1. User account executing PowerShell.
2. PowerShell command line.
3. Parent process.
4. Process creation time.
5. Computer name.
6. Process ID and Process GUID.
7. Any network connections generated by the process.
8. Whether the activity is expected administrative activity.

---

## Lab Analysis

The detected activity was generated intentionally for testing.

The PowerShell command executed a harmless message and did not perform malicious actions.

Therefore, the event was classified as:

**Benign / Expected Lab Activity**

---

## Recommended SOC Response

If this were a real-world alert:

1. Validate the user and host.
2. Decode the Base64 PowerShell command.
3. Determine whether the command is legitimate.
4. Review the parent process.
5. Search for related network connections.
6. Search for additional PowerShell activity.
7. Check for persistence or credential-access activity.
8. Escalate if malicious behavior is confirmed.

---

## Conclusion

The SOC detection successfully identifies PowerShell processes using encoded-command parameters.

The lab demonstrates how Sysmon Event ID 1 can provide process and command-line information to Splunk for security monitoring.
